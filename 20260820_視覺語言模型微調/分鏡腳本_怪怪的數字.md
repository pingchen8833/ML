# 怪怪的數字

> 教學短片分鏡腳本 · 片長 2:55 · 12 個鏡次 · 旁白約 490 字（語速 170 字/分）

四個真實的 bug，藏在一份公開發表、看起來很專業的機器學習專案裡。
沒有一個是靠讀 code 讀出來的——**全部都從一個看起來不對勁的數字開始。**

片中所有數字皆取自實際執行輸出。

---

## 開場｜一行輸出　`0:00 – 0:16`

### 鏡次 01 · `0:00 – 0:08`

**畫面**　全黑。畫面正中只有一行終端機輸出，游標在後面閃。停三秒不動，讓觀眾自己去讀那個數字。

```
BLEU : {'bleu': 0.0421, ... 'length_ratio': 2.0512}
```

**旁白**　這個數字，來自一份公開發表在 GitHub 和 Hugging Face 上的專案。它沒有紅字、沒有報錯，程式從頭到尾跑完了。

### 鏡次 02 · `0:08 – 0:16`

**畫面**　鏡頭推近，`2.0512` 撐滿畫面，其餘文字虛化。

**旁白**　但它其實在說一件事：我們產生的每一句話，都比標準答案長了一倍。

**字幕**　`length_ratio = 2.05`

## 背景｜它做對的事　`0:16 – 0:38`

### 鏡次 03 · `0:16 – 0:38`

**畫面**　Colab 畫面快轉：unsloth 啟動橫幅、訓練 loss 曲線往下掉、天文影像一張張閃過。節奏明快，像在誇獎它。

**旁白**　先說它做對的事。在一張免費的 T4 顯示卡上，微調一個 **110 億**參數的視覺語言模型。用 4-bit 量化把權重壓到 5 GiB，用 LoRA 讓只有 **0.63%** 的參數需要更新。這件事本身，幾年前還做不到。

**字幕**　`10,737,395,235 → 67,174,400 可訓練`

## Bug #1｜Prompt 回音　`0:38 – 1:12`

### 鏡次 04 · `0:38 – 0:54`

**畫面**　切回開場那行數字。旁邊並排三筆「Predicted / Reference」的範例，看起來長度差不多——製造矛盾。

**旁白**　回到那個 2.05。奇怪的是，隨手抽三筆出來看，長度明明差不多。那多出來的一倍，藏在哪裡？

### 鏡次 05 · `0:54 – 1:12`

**畫面**　把「完整的」Predicted 字串印出來。前半段整段 prompt 用琥珀色反白——原來題目被整個抄了一遍。

**旁白**　把完整輸出印出來就看到了：模型把題目抄了一遍，才開始寫答案。因為 `model.generate` 回傳的是輸入加輸出的**完整序列**，直接整條 decode，prompt 當然跟著印出來。分母被污染，BLEU 被低估。

**字幕**　`Bug #1 · Prompt 回音`

## Bug #2｜測試集根本沒被隔離　`1:12 – 1:42`

### 鏡次 06 · `1:12 – 1:28`

**畫面**　兩行程式碼上下並排，中間畫一條線連起來：上面用整份 `df` 訓練，下面又從整份 `df` 切測試集。

**旁白**　第二個 bug 更嚴重，而且它不在評估裡，在更前面。訓練用的是整份資料。然後，測試集又從整份資料裡切出來。

### 鏡次 07 · `1:28 – 1:42`

**旁白**　兩個集合一比，重疊 **100%**。模型在考試之前，看過每一張考卷。

**字幕**　`Bug #2 · 資料洩漏 100%`

## Bug #3｜裝飾品參數　`1:42 – 2:04`

### 鏡次 08 · `1:42 – 2:04`

**畫面**　程式碼特寫 `temperature=1.0`，游標在後面找 `do_sample`——找不到。接著切到 `print(model.generation_config)` 的輸出。

**旁白**　第三個很小，但很典型。評估迴圈傳了 temperature，卻沒有傳 do_sample。而 temperature 只有在取樣時才有作用——沒傳 do_sample，這個參數就是**裝飾品**。那到底用了什麼設定？來自模型自己帶的設定檔。同一行程式碼，換一個模型，行為就變了。

**字幕**　`Bug #3 · 明確永遠勝過依賴預設值`

## Bug #4｜缺口不是 28 MiB　`2:04 – 2:42`

### 鏡次 09 · `2:04 – 2:16`

**畫面**　氣氛一轉。滿版的紅色 OOM 錯誤訊息灌進畫面，音效重一點。

**旁白**　最後一個，是這份 code 裡唯一會直接爆炸的。它把 LoRA 合併成完整模型，然後用 16-bit 載回 T4。

```
OutOfMemoryError: CUDA out of memory.
Tried to allocate 28.00 MiB.
GPU 0 has a total capacity of 14.56 GiB
  of which 9.81 MiB is free.
14.40 GiB is allocated by PyTorch, and
21.48 MiB is reserved but unallocated.
If reserved but unallocated memory is large
try setting PYTORCH_CUDA_ALLOC_CONF=...
```

### 鏡次 10 · `2:16 – 2:30`　← 全片轉折

**畫面**　滑鼠游標移向最後那行建議，正要反白複製——畫面**凍結**，游標停住。然後鏡頭往上移，highlight `21.48 MiB`。

**旁白**　很多人看到這裡，會直接去複製最後那行建議。但那行有前提：「**如果**未使用的保留記憶體很大」。往上看——它是 21 MB。一點都不大。沒有東西可以回收，那行建議在這裡完全無效。

**字幕**　`錯誤訊息附的建議，也是一個待驗證的假設`

### 鏡次 11 · `2:30 – 2:42`

**畫面**　長條圖：一條 20.00 GiB 的模型，一條 14.56 GiB 的顯卡，差距用琥珀色標出來。`28 MiB` 那一小格小到幾乎看不見。

**旁白**　真正的缺口，不是 28 MB，是 **5.44 GiB**。模型是這張卡的 **1.37** 倍——從頭就放不進去。OOM 訊息永遠只報最後那一次要不到的配置，那個數字跟你差多少，完全無關。

**字幕**　`缺口 5.44 GiB，不是 28 MiB`
